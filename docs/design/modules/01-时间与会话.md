## 1. 模块目标与玩家感受

- 一个「镇日」= 白天正经开铺 + 夜里翻夜账，两段都是在做生意。
- 白天决策密、可多存；夜里履约一旦进现场，就不能靠反复读档把同一场「掷到满意」。
- 时间紧时感到「只够办几件大事」：看 AP 比看时钟更准；挂钟只告诉你气氛到哪一段了。

---

## 2. 规则全文

### 2.1 时间单位

| 单位 | 定义 | 边界 |
| --- | --- | --- |
| 镇日 | 完整一天：日档 + 夜档 | 主线约 12–20 个镇日可通（体量对应 8–15h） |
| 日档 | 阳间营业：接谈/备料/交货/铺务/打听/进货等 | 有效操作目标手感 10–18 min |
| 夜档 | 诡异接单 + 履约 + 收摊 | 5–12 min；含 bridge 未履约的强制待办 |
| 节气/庙会日 | 特殊镇日标签 | 可强制排顶格候选或改刷新权重（见 04、07） |

### 2.2 日档行动限制 · **本稿默认：混合制**

> **相对变更（相对 v0.1d 开放点）**：落地为混合制，不再双案并列进主 UI。

| 规则 | 内容 |
| --- | --- |
| 日档 AP 总量 | 【示例】6；每日日初重置 |
| 接谈（看单/接拒/议价链） | 1 AP / 次；交货并入接谈链，不另扣 |
| 备料/工艺 | 1 AP / 批次（可一次处理多单若 UI 允许） |
| 铺务（修铺/安抚伙计/送礼） | 1 AP |
| 打听 | 1 AP（09） |
| **进货** | **单独扣 1 AP**（本稿默认；不并入铺务） |
| 挂钟三段 | 午前 / 午后 / 傍晚：仅氛围条 + **时段解锁/打烊软约束**；**不**单独扣「重大决策次数」 |
| 软约束【示例】 | 某些剧情客「只午前出现」；傍晚出现「催落锁」提示；AP 耗尽可提前落锁 |
| 夜档 | **不耗日档 AP**；夜有独立接单次数与履约回合 |

**备选（不进主 UI）**：纯 AP；纯时段制——见 §8。

### 2.3 日 → 夜交接（落锁）

玩家选「落锁营业」或傍晚强制落锁：

1. 播放短过场（账本翻到夜页；可冷幽默）。  
2. 执行 **日末结算**（02）。  
3. 生成夜单池；推入未履约的 bridge 待办。  
4. 进入夜账接单界面（**可存档**）。

### 2.4 夜 → 次日交接（收摊）

1. 所有已接夜单必须进入履约或明确「压下/跑路/失败」结算；bridge 未履约视同普通夜失败。  
2. 执行 **夜末结算**（02）。  
3. 进入次日日初；刷新阳单池；应用具名后果（封门、少单等）。

### 2.5 存档

| 时机 | 允许 | 读档落点 |
| --- | --- | --- |
| 日档·柜台任意可存点 | 是 | 当日日档该存点 |
| 夜账·接单界面 | 是 | 接单界面（未进现场） |
| 夜履约·进入现场后至结算前 | **禁止**（本稿默认；无检查点） | 读档回「夜账接单界面」，不回滚现场内上一步 |
| 坏结局后 | — | 回上一日日初（06） |

边界：不鼓励同一现场反复重 roll；允许玩家用「少接夜单」作为合法降压。

### 2.6 会话中断

| 情况 | 处理 |
| --- | --- |
| 强制退出（崩溃等） | 回最近合法存档 |
| 夜现场中途退出 | 视同读档回接单界面；已锁定材料仍锁定至该夜结算或弃单 |

## 4. 操作流

### 4.1 日档耗 AP 动作路径

1. 玩家从柜台/街巷发起动作（接谈、备料、铺务、打听、进货）。  
2. 系统预检 `AP_left`：不足 → 按钮灰 + 气泡 `no_AP`。  
3. 确认动作 → `AP_left -= cost` → 进子流程。  
4. AP=0：落锁按钮高亮脉冲；其他耗 AP 入口全灰。

### 4.2 挂钟软约束

1. 时段随「完成耗 AP 动作」或「手动推进气氛」推进【示例】：每 2 AP 可推进一段，或固定节点事件推进。  
2. **本稿默认**：时段推进**不另扣**决策次数；仅控制「谁出现/是否催落锁」。  
3. 傍晚：若玩家仍有 AP，可继续办；点落锁或点「打烊提示」确认。

### 4.3 落锁点击流

1. HUD/柜台 `[落锁营业]`。  
2. 若有逾期未交阳单 → `UI_Confirm`：「未交货将按失败结算」。  
3. 确认 → 仪式屏 → 夜接单；自动存。

### 4.4 存档点击流

1. 菜单 → 存档：若 `shell_state==NIGHT_FULFILL` → 存档按钮灰 + toast。  
2. 读档选槽 → 若槽标记在履约中途（不应存在）→ 修正落到夜接单。  
3. 坏结局后「回到上一日」→ 直接读系统标记的日初档。

### 4.5 异常态

| 情况 | 表现 |
| --- | --- |
| AP 不足 | 灰显 +「今天只够办这些了」 |
| 履约中存档 | 灰显 +「履约中不能存档」 |
| 夜未了账点收摊 | 拦截「还有夜账没了」 |
| 崩溃恢复 | 主菜单「继续」指向最近合法档 |

## 5. 反馈

| 事件 | 反馈 |
| --- | --- |
| AP 扣除 | HUD AP 格一格熄灭；轻叩 SFX |
| AP 耗尽 | 落锁钮呼吸光；远景店铺收声 |
| 时段切换 | 挂钟响一下；光色微变 |
| 落锁翻页 | 见 00a |
| 禁存 | toast + 短闷音 |

## 8. 开放点 / 待 Charlie 拍板

1. **AP vs 时段 vs 混合**——**本稿默认混合制**（AP 主计 + 挂钟软约束）。备选：纯 AP；纯时段。  
2. 进货是否单独扣 AP——**本稿默认单独 1 AP**。备选：并入铺务。  
3. 夜履约现场内检查点存档——**本稿默认否**。  
4. 节气/庙会日数量与是否强制顶格。  
5. 时段推进与 AP 消耗的具体挂钩公式（软约束强度）。
